# Transaction, not writeBatch, for moving an Item between Lists

`moveItemToList` (the delete-in-source + create-in-dest write behind dragging an Item into a different List) uses `runTransaction` instead of `writeBatch`, which every other multi-operation write in `itemService.ts`/`listService.ts` uses. A plain batch can't detect two races this specific operation is exposed to: two Members moving the same Item to two different Lists at once (`deleteDoc` is idempotent and the two `set()`s land on different collections, so both batches would succeed independently and silently duplicate the Item), or a Member moving an Item into a List another Member deletes at the same moment (a plain batch would resurrect an Item under a now-gone List path, invisible forever, since ADR 0001's cascade delete only touches Items that existed at delete time). We considered keeping `writeBatch` for consistency with the rest of the codebase, but rejected it: both races silently corrupt data rather than fail loudly, which a single extra read (checking the source Item and destination List both still exist before committing) is a cheap way to close.
