# Transaction, not writeBatch, for moving an Item between Lists

`moveItemToList` (the delete-in-source + create-in-dest write behind dragging an Item into a different List) uses `runTransaction` instead of `writeBatch`, which every other multi-operation write in `itemService.ts`/`listService.ts` uses. A plain batch can't detect two races this specific operation is exposed to: two Members moving the same Item to two different Lists at once, or a Member moving an Item into a List another Member deletes at the same moment. We considered keeping `writeBatch` for consistency with the rest of the codebase, but rejected it: both races silently corrupt data (a duplicated or orphaned Item) rather than fail loudly.

The two races get different strength guarantees. The same-Item-two-movers race is **fully closed**: both transactions delete the same source document, a genuine write-write conflict, so Firestore's optimistic concurrency control serializes them — the loser's `transaction.get()` retries against fresh state, sees the source gone, and returns `source-missing`. The deleted-destination-List race is only **narrowed, not closed**: `deleteList` (`listService.ts`) isn't itself transactional — it snapshots the List's Items via a plain `getDocs()`, then deletes them across chunked `writeBatch`es (a genuine transaction can't be used there; a large List's cascade delete can exceed a single transaction's operation limit). If a move's transaction reads "destination List exists" and commits while a concurrent `deleteList` is between its `getDocs()` snapshot and its final batch, the newly-moved Item can still end up orphaned under the now-deleted List path — it just requires much tighter timing (an in-flight list deletion, not merely "list already gone") than the fully-closed case. We accept this residual as the same class of low-stakes, family-scale concurrency risk ADR 0002 already accepts for reorder-drift — closing it fully would mean making `deleteList`'s cascade itself race-proof, a bigger change than this feature warrants.
